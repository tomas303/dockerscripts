# droid - LineageOS build container

Image with everything needed to build LineageOS (tested for `lineage_toco`),
sign the build with own keys and flash it. Source tree, keys and results live
in the home directory of the container (distrobox with dedicated home), not in
the image.

## How the image is constructed

- `Dockerfile` - debian stable + packages for android build (build-essential,
  multilib, ccache, git-lfs, python, ...), packages for emulator, `usbutils`
  and `android-sdk-platform-tools-common` (flashing). Copies `scripts/*.sh` into
  `/opt/scripts` and runs `installrest.sh`. Default command is a login shell.
- `scripts/installrest.sh` - installs `repo` into `/usr/local/bin`, downloads
  google platform-tools (`adb`, `fastboot`) into `/opt/android/sdk` and copies
  `droidenv.sh` into `/etc/profile.d`.
- `scripts/droidenv.sh` - runs on every login shell: sets git user/email,
  PATH to platform-tools, ccache, `WITH_GMS=true` and all `EVDOCKER_*` build
  variables (see below). Every variable can be overridden before login.
- `scripts/genkeys.sh` - generates own signing keys (never overwrites).
- `scripts/signbuild.sh` - build + sign + create ota zip.
- `build.sh` - `podman build -f Dockerfile -t droid .`

### Variables (defaults in `droidenv.sh`)

| variable | meaning | default |
|---|---|---|
| `EVDOCKER_LINEAGEDIR` | lineage sources | `~/android/lineage` |
| `EVDOCKER_KEYSDIR` | own signing keys (**back them up**) | `~/android/keys` |
| `EVDOCKER_OUTDIR` | signed results | `~/android/signed` |
| `EVDOCKER_LUNCH_TARGET` | lunch target | `lineage_toco-userdebug` |
| `EVDOCKER_CERT_SUBJECT` | subject of generated certificates | see file |
| `EVDOCKER_KEY_NAMES` | keys generated by `genkeys.sh` | see file |
| `EVDOCKER_OTA_KEY` | key signing the ota zip | `releasekey` |
| `EVDOCKER_GEN_AVB` | 1 = generate AVB key too (toco can't enroll it) | `0` |
| `EVDOCKER_SIGN_EXTRA_ARGS` | extra args of `sign_target_files_apks` | empty |
| `EVDOCKER_OTA_EXTRA_ARGS` | extra args of `ota_from_target_files` | empty |
| `EVDOCKER_MKA_JOBS` | `-j` for `mka` | empty (all cores) |

Image-level variables (Dockerfile): `EVDOCKER_SCRIPTSDIR`, `EVDOCKER_SDK`,
`EVDOCKER_SDKPLATFORMTOOLS`, `EVDOCKER_GITEMAIL`, `EVDOCKER_GITUSER`,
`EVDOCKER_USE_CCACHE`, `EVDOCKER_CCACHE_SIZE`.

## Create the container

```
./build.sh
distrobox create \
  --name droidbuilder \
  --home <dedicated home directory> \
  --image localhost/droid:latest
distrobox enter droidbuilder
```

The phone must be accessible from the container (distrobox shares host
devices) - udev rule on the host, e.g. `/etc/udev/rules.d/51-android.rules`:

```
SUBSYSTEM=="usb", ATTR{idVendor}=="18d1", ATTR{idProduct}=="4ee7", MODE="0660", GROUP="<somegroup>", SYMLINK+="android%n"
```

## Sources (one time / when updating)

```
cd $EVDOCKER_LINEAGEDIR
repo init -u https://github.com/LineageOS/android.git -b lineage-20.0 --git-lfs
# put local manifest (device tree, vendor, kernel, gapps) into .repo/local_manifests
repo sync        # sometimes hangs at 99%, interrupt and run again
```

## Build

Build signed with own keys (instead of `mka bacon`):

```
/opt/scripts/signbuild.sh
```

It does `lunch $EVDOCKER_LUNCH_TARGET`, `mka target-files-package otatools`,
generates missing keys (regular keys and one key per APEX found in the build),
`sign_target_files_apks`, `ota_from_target_files` and writes into
`$EVDOCKER_OUTDIR`:

- `signed-ota_update.zip` - for `adb sideload`
- `signed-target_files.zip`
- `recovery.img` - recovery signed with own keys (if present in target files)

If signing complains about an APK without a key, add it to
`EVDOCKER_SIGN_EXTRA_ARGS`, e.g.
`--extra_apks Name.apk=$EVDOCKER_KEYSDIR/releasekey`.

Unsigned (test keys) build, the old way:

```
cd $EVDOCKER_LINEAGEDIR
. build/envsetup.sh
lunch lineage_toco-userdebug
mka bacon
```

Run `mka clean` before a rebuild when previous parts could interfere.

## Flash

`adb` and `fastboot` are in `/opt/android/sdk/platform-tools` (already in PATH).

First flash of own keys (or whenever keys change) **needs a data wipe** and
recovery signed with the new keys, because the old recovery only trusts the old
ota key (backup first; Google backup does not cover `/sdcard`):

```
fastboot flash recovery $EVDOCKER_OUTDIR/recovery.img
fastboot reboot recovery
# in recovery: Factory reset -> Format data / factory reset
# then: Apply update -> Apply from ADB
adb -d sideload $EVDOCKER_OUTDIR/signed-ota_update.zip
```

Next updates signed with the same keys (data is kept):

```
adb reboot recovery
# Apply update -> Apply from ADB
adb -d sideload $EVDOCKER_OUTDIR/signed-ota_update.zip
```

Sometimes recommended for toco: `fastboot wipe-super super_empty.img`
(image is somewhere in `out/`), not sure it is needed.

## Notes

- Keys protect: apk/apex signatures (package manager), ota signature
  (recovery). The bootloader is not involved - toco can't enroll custom AVB key,
  so bootloader stays unlocked.
- Losing `$EVDOCKER_KEYSDIR` means a new key set and another data wipe.
- gapps (`vendor/gapps`, MindTheGapps) are part of the manifest, because system
  partitions are erofs (read-only) and gapps can't be sideloaded afterwards.
